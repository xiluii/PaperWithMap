# 划词翻译验收

日期：2026-10-16。

## 行为与边界

- 平台内的 PDF、PPT 连续预览与 Word 编辑页提供同一「划词翻译」开关，默认关闭，偏好保存在当前浏览器。
- PDF / PPT 使用可选择的文字层；Word 通过 SuperDoc 扩展的 `onSelection` 与 `doc.selection.current({includeText:true})` 读取当前选区，不修改正文。
- 选词稳定后通过本地 `POST /api/dictionary/lookup` 查询有道词典公开接口，仅请求中英词典与音标数据，返回纯文本释义。没有 GPT、Codex、登录或密钥依赖，也没有 AI 回退。
- 超出 120 字符、20 个词的选区在前后端均被拒绝；只包含数值或符号的选区不查询。未收录时明确提示，网络失败可重试。
- 关闭、切换选区、关闭阅读器会取消本地请求；晚到的结果不会重新弹出。已完成的释义最多在服务内存中缓存 200 条、30 分钟，不落盘。
- 词典查询只发送选中文字，不携带文件、文件名、笔记或聊天。服务采用有道公开网页查询接口，非具有稳定性承诺的授权开放平台 API。

## 自动验证

`npm test`：39 项前端单元测试与 45 项 Node 集成测试，共 84 项通过。

新增验证覆盖 PDF 断行与词条规范化、选区长度限制、固定上游地址及词典范围、完整中英释义解析、未收录、内存缓存、上游异常与超时、本地 HTTP 来源限制、查询不落盘、客户端取消向上游传播。自动测试使用本地仿真，不依赖公共词典或真实 AI 额度。

`npm run build`：TypeScript 与 Vite 生产构建通过。Word 编辑内核沿用原有大体积分块提示。

## 浏览器实机验证

使用独立测试数据目录及合成 PDF、DOCX、PPTX，不操作个人文献或真实聊天。另用公开单词对真实有道接口进行连通与释义验证。

| 场景 | 结果 |
| --- | --- |
| 默认关闭后双击 PDF 单词 | 无翻译浮层，词典 HTTP 请求数为 0 |
| 开启后选择 research | 显示真实英美音标及完整词性释义 |
| 关闭后另选新词 | 无浮层，请求计数保持不变 |
| Word 内核选区 | Research 返回词典释义，文档仍保持已保存状态 |
| PPT 预览文字层 | reading 正常查询 |
| 切换文件 | 开关偏好保留 |
| 暗色、专注模式、收起侧栏 | 开关和词典查询均可用，无工具栏重叠 |
| 未收录词条 | 显示未收录提示，不替换成相似词 |
| 接近页面底部 | 浮层向上排布，保持在视口内 |
| 页面滚动 / Esc | 仅关闭翻译浮层；Esc 不误关阅读器 |
| 词典浮层中的「向 AI 提问」 | 转到 AI 标签并保留引用选区；查询本身不创建对话 |

实机截图保存在本地忽略目录 `artifacts/reading-translation-dark.png`。测试没有产生 AI 对话或消耗真实 AI 额度。
